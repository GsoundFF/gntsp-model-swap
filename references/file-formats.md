# 文件格式笔记（实测）

本页记录的是**在本作（Wii `Naruto Shippuuden Gekitou Ninja Taisen! SP`，
光盘 ID 3800805）上实测得到**的结构，不是通用规范。数字都来自原版文件。

---

## 1. FPK 容器

FPK 是 Eighting 的归档格式，本作里每个角色一个：
`DATA/files/fpack/chr/<code>/0000.fpk`。
同一份内容也以「散装」形式放在 `DATA/files/chr/<code>/`，两边要一起改。

### 头部（16 字节，big-endian）

| 偏移 | 类型 | 含义 |
|---|---|---|
| `0x00` | u32 | 校验和 = 所有子文件**压缩后**字节之和 `& 0xFFFF` |
| `0x04` | u32 | 子文件数量 |
| `0x08` | u32 | 条目表起始偏移（本作恒为 `16`） |
| `0x0C` | u32 | 文件总大小（含末尾填充） |

### 条目表（每条 48 字节，紧跟头部）

| 大小 | 含义 |
|---|---|
| 32 | 名称，Shift-JIS，`\0` 填充 |
| 4 | 保留，恒为 0 |
| u32 | 数据偏移（相对文件开头） |
| u32 | **压缩后**大小 |
| u32 | **原始**大小 |

每个子文件的数据按 **16 字节对齐**排放，条目之间的空隙用 `\0` 填充。

### 压缩

- `压缩后大小 == 原始大小` ⇒ 该子文件**原样存储**，没有压缩。
- 否则用 **Eighting PRS** 压缩。

Eighting PRS 与经典 Nintendo PRS 是近亲，**flag 位极性相反**：
读到 `1` 表示「下一个字节是字面量」，读到 `0` 再读一位区分短/长回溯。
短回溯用 8 位有符号偏移 + 2 位长度；长回溯用 13 位偏移 + 3 位长度
（低 3 位为 0 时再读一个扩展长度字节）。
`scripts/fpk_tool.py` 里的实现与社区 GNTool 的编解码器一致。

**重新压缩一定比原版大**（实测 krn：`1187936 → 1287312`，约 +8.4%）。
这是正常的，游戏接受。

### 自检

```powershell
python scripts\fpk_tool.py roundtrip <原版.fpk>
```

会解包、重压、再解包，逐条比对是否逐字节一致，并报出大小变化。
**换新游戏版本时先跑一次这个**，通过再动手。

## 2. BRRES 模型（`0000.brres`）

BRRES 是 Wii 的标准资源容器，模型在里面叫 **MDL0**。

- 文件开头是 BRRES 头（`BRRES\0` + 版本等），MDL0 资源紧跟在后面：
  实测 krn 在 `0x0000e0`，hnt 在 `0x000100`（各角色不同，**必须搜索 magic 定位**，
  不要写死偏移）。
- MDL0 头 `+0x04` 是 MDL0 自身大小；
  `+0x10` 起是 **12 个 u32 段偏移**，全部**相对于 MDL0 起始**。

### 骨骼字典段

12 个段里，**每根骨骼恰好 16 字节**的那一段就是骨骼字典：

```
段大小 = 0x18 + 骨骼数 × 16
```

条目从段起始 `+0x18` 开始，每 16 字节：

| 偏移 | 类型 | 含义 |
|---|---|---|
| `+0x00` | u16 | **骨骼编号**（跨角色共享的编号空间） |
| `+0x02` | u16 | 未确定（实测多为 0） |
| `+0x04` | u16 | 字典树的左/右链接（取值 0..骨骼数） |
| `+0x06` | u16 | 同上 |
| `+0x08` | u32 | 用途未确定（不是可靠的名字指针） |
| `+0x0C` | u32 | 骨骼变换数据偏移 |

**关键**：`+0x00` 的骨骼编号来自一套**所有角色共用**的编号空间。
krn 与 hnt 共享 35 个编号，但排列顺序不同 —— 35 个共享编号里只有 1 个
落在相同的位置上。这就是「整文件覆盖模型会崩」的根本原因，
也是「动画可以跨角色复用」的原因（`.mot` 通过这套共享编号寻址骨骼）。

用 `scripts\brres_bones.py` 可以直接读出这些数字：

```powershell
python scripts\brres_bones.py krn\0000.brres hnt\0000.brres
```

### 名字表

BRRES 的字符串表是「u32 长度 + 内容 + 4 字节对齐」的序列，
本作里骨头大多只有自动生成的占位名（`#0`、`#1`……），
少量有真名（如 `L_collar`、`L_finHi01`、`DrawOpa`）。
**不要依赖骨骼名做映射** —— 骨骼编号才是可靠依据。

## 3. 其它文件

| 文件 | 说明 |
|---|---|
| `0000.mot` | 动画。按全局骨骼编号驱动，所以能跨角色复用 |
| `0000.seq` | 招式逻辑脚本（Eighting 自有的字节码） |
| `0000.brtex` | 贴图资源 |
| `0000.brplt` | 调色板资源 |
| `*.brsca` | 镜头动画 |
| `*.breff` / `*.breft` | 特效定义 / 特效贴图 |

本仓库的方法**只替换模型与贴图/调色板**，不解析 `mot` / `seq` / `breff` 的内部结构。
想改招式或动画，参见社区项目
[GNTool](https://github.com/NicholasMoser/GNTool) 与
[Naruto-GNT-Modding](https://github.com/NicholasMoser/Naruto-GNT-Modding)。
