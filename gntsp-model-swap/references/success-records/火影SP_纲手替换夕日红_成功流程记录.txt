成功调试流程记录（用于后续回顾）

一、目标
----------------------------------------
把纲手(tnd)的模型放到夕日红(krn)的选人槽位上，
战斗中的动作、招式仍然保持夕日红。

----------------------------------------

   实测游戏正常运行，属于无害误报，直接无视即可。
   不要为此去启用 Dolphin 的 MMU（会变慢，甚至可能真的卡住）。
3. 原始 wbfs 镜像全程未改动。

四、完整制作流程（以后换其他角色可复用）
----------------------------------------
【0】环境与原料
    - 游戏镜像：D:\Games\WII\3800805\3800805.wbfs
    - Dolphin：E:\Dolphin\Dolphin-x64\Dolphin.exe
    - 工具（都在 D:\Games\WII\3800805\ 下）：
      fpk_tool.py          FPK 解包 / PRS 压缩 / 打包
      brres_analyze.py     brres 模型结构分析（骨骼表等）
      build_swap.py        自动生成版本1
      build_swap_full.py   自动生成版本2
      .tools\DolphinTool   提取镜像用
      .tools\Naruto-GNT-Modding  社区资料（动画格式说明 mot.md 等）

【1】把镜像解成"Dolphin 可直接运行的目录版游戏"
    DolphinTool extract -i 3800805.wbfs -o <目标目录> -g
    -g 只解 DATA 分区；解出的文件夹内含 sys\main.dol，
    Dolphin 直接"打开"这个 main.dol 即可运行，无需重打包 wbfs。

【2】解包角色 FPK
    python fpk_tool.py unpack <xxx.fpk> <输出目录>
    - 角色文件在：DATA\files\fpack\chr\<角色代码>\0000.fpk
    - 角色代码：krn=夕日红，tnd=纲手
    - 同一目录 DATA\files\chr\<代码>\ 下还有同名"散装"文件，两者内容一致。
    - FPK 内包含：chr/<代码>/0000.seq（招式逻辑）、
      0000.brres（主模型）、0001.brres（副模型）、0000.mot（动画）、
      0000.brtex（贴图），以及 cam/cpu/eft（镜头/电脑AI/特效）。

【3】替换模型（本次实际操作）
    版本1（保留夕日红动作）：
      a. 把 tnd 的 0000/0001/0002/0100.brres、0000/0100.brtex、
         0000/0100.brplt 复制覆盖到 krn 的散装目录同名文件；
      b. 保留 krn 的 0000.mot 和 0000.seq 不动；
      c. 重建 krn 的 0000.fpk：解包后用 tnd 的
         0000.brres / 0001.brres / 0000.brtex 替换其中同名条目，
         其余条目（seq/mot/cam/cpu/eft）保持 krn 的，再打包回去。
    版本2（完整纲手）：
      把 tnd 的所有文件整体换成 krn 的，FPK 也用 tnd 内容重建
      （包内路径改成 krn）。

【4】重新打包 FPK
    python fpk_tool.py pack <输出.fpk> <磁盘文件=包内路径> ...
    - 自带 Eighting PRS 压缩/解压，往返一致已验证。
    - 重压后的 FPK 会比原版稍大（例：krn 0000.fpk
      1187936 -> 1287312 字节），格式合法，可正常运行。

【5】在 Dolphin 测试
    文件 -> 打开 -> 选目录版游戏的 DATA\sys\main.dol
    进对战选"夕日红"。


五、本次调试中发现的关键点
----------------------------------------
1. 骨骼差异：
   krn 骨骼 78 根，tnd 94 根，且顺序不同，
   因此不能整文件覆盖模型，必须"只换网格/贴图"。
2. 动画可跨角色复用：
   动画(0000.mot)按"全局骨骼编号"驱动骨骼，而非本地序号，
   所以"换模型、不动动画"可以成功。
3. 游戏读取路径：
   main.dol 字符串里同时有 fpack/chr/%s/ 和 chr/%s 两种路径，
   散装文件与 FPK 都可能被读取，稳妥做法是两处都改。
4. 报错提示：
   启动后可能反复出现"无效读取"警告，实测不影响运行，忽略。
5. 原始文件备份：
   D:\Games\WII\3800805\mod\game_root\ 是从 wbfs 解出的完整原始
   游戏树，保留作底稿，重新制作时从它复制再改。
